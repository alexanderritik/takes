StorageVersions, not exports

Five versions. Your footage, once.

A folder of exports holds the whole video again for every version, and still cannot tell you what changed. Takes never copies or renders video. A version is the timeline: which clip plays, from which frame to which. Your footage stays in your project folder, where your tool keeps it.

SC 02The request

An agent's edit lands on a side line, never on main.

Each agent checks out the timeline, edits it however it likes and submits it back as a request. A person reads exactly what changed, clip by clip, and approves it or not.

SC 03Many agents at once

Parallel edits combine clip by clip. Collisions come back as data.

Three agents can work on one cut at the same time. Edits to different clips, or to different fields of one clip, are all kept. When two change the same thing, approve stops, main stays as it was, and you get the conflict to act on.

SC 04The record

Who changed which clip, when, and why.

Every version is kept and can be checked out again, without a single extra copy of your footage. Blame names the last person or agent to touch each clip. Revert takes main back as a new version, so nothing is ever erased.

SC 05Built for programs

One binary. Timelines go in as JSON and JSON comes out.

Your program calls takes, reads one JSON document from stdout and branches on the exit code. There is no library to link and no server to run. AI agents get the same commands as tools over MCP.

  • Your media

    Videos are referred to, never copied. Takes opens only files inside the project folder and fingerprints them, so a file swapped under the same name shows up in review.

  • Your fields

    Every other field is kept. Colour, transitions and effect settings ride along as sent and merge one field at a time, so two agents setting fx.a and fx.b both land.

  • Frames

    Every time is a whole frame at the project's rate, including 30000/1001. Shapes are frozen by golden tests; the format only grows.
